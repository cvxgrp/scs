# Benchmark problems in the tests

The nine headers in this directory hold problems from three public collections
of test problems, each exactly as the
[solver_benchmarks](https://github.com/bodono/solver_benchmarks) harness poses
it for SCS. `test/problems/test_benchmark_problems.h` solves them in
`run_tests`; its comments say what each test checks and the builds where a
problem is skipped.

**SCS does not control the licence of these data.** None of the three
collections states a licence for its problem files. What each one publishes
is set out below, as found on 2026-11-24, with the source's own words linked.
SCS's licence (`LICENSE.txt`) is for SCS and does not extend to these files.
Check the source's terms before reusing them.

How each file reached the harness:

- **SDPLIB:** the harness bundles a conversion of the SDPLIB `.dat-s` files to
  JLD2 (`sdplib.tar`); the converter is not recorded.
- **Netlib:** the harness holds the `lp/infeas` files decoded from netlib's
  compressed form to MPS; how is not recorded.
- **Maros-Mészáros:** the `.mat` files were converted from CUTEst's SIF
  version of the set by the OSQP benchmarks
  (<https://github.com/osqp/osqp_benchmarks>), whose copies are byte for byte
  the same.

How the harness poses them for SCS:

- **SDPs:** its SDPLIB loader poses minimize c'x subject to
  sum_i x_i F_i - F_0 positive semidefinite, in the block structure SDPLIB
  declares, as A x + s = b with s in the PSD cone: column i of A is
  -svec(F_i) and b = -svec(F_0) (the lower triangle by columns, off-diagonal
  entries times sqrt(2)).
- **LPs and QPs:** its loader reads l <= A x <= u (the MPS reader adds a row
  of the identity for each variable with a finite bound; the Maros-Mészáros
  files hold those rows already), and its SCS adapter
  (`qp_to_scs_box_cone`) puts the equality rows in the zero cone and the
  others in one box cone (t, s), t l <= s <= t u, whose first row says t = 1
  (a zero row of A, b = 1) and whose other rows are s_j = a_j'x (row -a_j of
  A, b = 0). Rows with no finite bound are left out.

The SDPs and the two LPs come with an empty P, which the headers pass as
`P = NULL`; SCS solves the two the same, bit for bit.

## Regenerating a header

1. **Write the SCS data file.** In the harness at the commit above, load the
   problem with its dataset (`solver_benchmarks.datasets.registry.get_dataset`
   with `"sdplib"`, `"netlib"` or `"maros_meszaros"`, and the option
   `subset="infeasible"` for infp1, infd2, galenet and itest2), and solve it
   with `solver_benchmarks.solvers.scs_adapter.SCSSolverAdapter` with the
   settings `write_data_filename="NAME.scs"` and `max_iters=1`. SCS then
   writes the data it was handed, before any scaling (`SCS(write_data)` in
   `src/rw.c`). The files used here were written by scs-python 3.3.1, and
   their SHA-256 sums are in the table above.
2. **Write the header.** `python3 gen_header.py NAME.scs` (standard library
   only) checks the file's SHA-256 against the one recorded in the script and
   writes `name.h` here, with this provenance and licence information at the
   top.

Every value is written as the shortest decimal that rounds back to it, which
a compiler that rounds decimal constants correctly, as gcc and clang do,
reads back to the same double; a single-precision build rounds it to float.
Read back with clang and gcc, in double and single precision and with 4- and
8-byte integers, every header gives exactly the data in its SCS data file.
