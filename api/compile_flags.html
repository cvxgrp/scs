Compile flags

Typically the user will not need to interact with these flags, but we document them here for completeness. The flags in the table below are defined in scs.mk (all but R_LANG, see its row) and can be overridden via the command line when compiling with the Makefile by executing, e.g., make DLONG=1, to set the DLONG flag to True. Only some of them are available in the CMake build, see below. Note this list is not exhaustive: more variables of the Makefile are listed below (those of the CUDA builds are on the install page), and further constants are not exposed but defined in include/glbopts.h.

Other Makefile variables

The Makefile also uses the variables below. They are set in the same way, e.g., make OPT=-O3 BLASLDFLAGS=-lopenblas.

Description

OPT

Optimization flags for the compiler. The default includes -march=native, so the libraries are tuned to the processor of the machine they are built on and may not run on a different one. Use, e.g., OPT=-O3 for libraries that will run on other machines. (The CMake build does not use -march=native)

OPT, PREFIX, MKLROOT, OMPROOT and CFLAGS can also be set as environment variables. BLASLDFLAGS, COVERAGE and the scs.mk flags of the first table are only read from the command line of make.

CMake

With CMake the flags are options that are set when configuring, e.g., cmake -DDLONG=ON ... The following flags of the first table are CMake options, with the same default: DLONG, SFLOAT, NO_PRINTING, NO_READ_WRITE, USE_LAPACK, BLAS64, USE_OPENMP, USE_PARALLEL_PSD and USE_SPECTRAL_CONES. GPU_TRANSPOSE_MAT is a CMake option too, but only together with -DUSE_GPU=ON.

CTRLC is always enabled in a CMake build. NO_TIMER, NO_VALIDATE, VERBOSITY, NOBLASSUFFIX and BLASSUFFIX are not CMake options, and CMake ignores them with a warning if they are passed as one (-DNO_TIMER=ON, say). They can be passed to the compiler directly, e.g., cmake -DCMAKE_C_FLAGS="-DNO_TIMER=1" ...

CMake finds the BLAS and LAPACK libraries itself. To choose a particular library set CMake’s BLA_VENDOR, e.g., cmake -DBLA_VENDOR=OpenBLAS ... If the MKLROOT environment variable is set and BLA_VENDOR is not, SCS asks CMake for MKL. If CMake finds no LAPACK, SCS links blas and lapack by name, except with BLAS64=ON, where the configuration stops with an error.

The options that select what is built (BUILD_SHARED_LIBS, BUILD_TESTING and the options for the other linear solvers) are described in the install and linear solver pages. CMake has two more options, which the Makefile does not have (there, pass the definition in CFLAGS):
