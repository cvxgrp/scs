At max_iters or time_limit_secs

When SCS stops at max_iters or time_limit_secs before its termination criteria hold, it reports what the last iterate supports. SCS works with a homogeneous iterate \((x, y, s, \tau, \kappa)\): a solution estimate is \((x, y, s) / \tau\), which needs \(\tau > 0\), and a certificate estimate is \(y / (-b^\top y)\) or \((x, s) / (-c^\top x)\), which needs \(b^\top y < 0\) or \(c^\top x < 0\). The tests below are exact comparisons, taken in this order, so the status depends only on the last iterate:

-7 or -6

\(\tau > 0\)

2

The solution estimate \((x, y, s) / \tau\) and its objective and residuals

Otherwise: \(\tau = 0\) and \(b^\top y \geq 0\), \(c^\top x \geq 0\)

-3 (SCS_INDETERMINATE)

x, y, s NaN, and pobj, dobj, gap, res_pri, res_dual, res_infeas, res_unbdd_a, res_unbdd_p and comp_slack NaN

Each status except failure ends in (inaccurate - reached max_iters) or (inaccurate - reached time_limit_secs), for example indeterminate (inaccurate - reached max_iters).

The last iterate is never built from an accelerated step that the acceleration safeguard rejected: AA makes no step at the last iteration, and the time limit is tested only at a convergence check, which reads only iterates the safeguard has accepted.

The estimates returned with 2, -6 and -7 do not meet the tolerances. A certificate estimate rests on the sign of \(b^\top y\) or \(c^\top x\) at the last iterate alone, which on a run whose iterates diverged can change from one iteration to the next.

SCS returns SCS_INDETERMINATE when the cone projection has set \(\tau\) to zero and neither \(b^\top y\) nor \(c^\top x\) is negative. This happens in the first few iterations and on runs whose iterates diverged. As for an inaccurate status, more iterations or more time can help (see SCS returns indeterminate). A warm start from the NaN solution starts from zero, as a cold start does (see Caching the workspace and warm-starts).
